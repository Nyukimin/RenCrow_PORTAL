# LIVING 趣味の作画と実行状態

COREが選んだ趣味をWORLDが開始し、その確定状態をPORTALが描画する。
吹き出しや時刻だけを根拠に、PORTALが趣味を開始することはない。

| 本人 | WORLDの活動 | 採用素材 |
|---|---|---|
| Mio | `fashion_show` | 準備・披露・瞬き・横姿・軽い回転・満足の6枚 |
| Shiro | `exercise` | 白スラックス・上半身裸・素足。ダンベル・筋肉ポーズ・腕立て・終了の6枚 |
| Kuro | `mirror_pose` | 鏡の確認・腕組み・腰に手・顔に手・満足の5枚 |
| Midori | `reading` | 本を開く・読む・ページをめくる・笑う・本を抱くの5枚 |

## 素材の正本と読込み

`internal/portal/web/living/assets/hobbies/catalog.json`は添付された各人の
`assets.json`をまとめたもの。`image_path`はこのディレクトリを基準に解決する。
原PNGは加工せず、22枚をそのまま収録した。ZIPのCRCと`files.json`にある全ファイルの
SHA-256を照合し、採用ZIPのハッシュを`provenance.json`に記録した。
各人の`SOURCE_NOTES.md`に元素材の制約を保持する。
`original_image_path`と編集用ファイルの参照は出典情報であり、実行時には使わない。

320×320の共通キャンバス、足元基準(160,318)を使う。伏せ姿勢を立位の高さまで
引き伸ばさない。Midoriの座面基準は素材側でも推定値であり、家具との接地は別に確認する。
静止画を順に差し替える素材で、中割りを備えた連続回転や立位から腕立てへの連続動作ではない。

表示用の開始・終了phaseは各0.6秒、通常の活動中フレームは0.8秒を基準とする。
Mioの披露・瞬きは素材ノートの推奨値（披露1.5秒、瞬き0.12秒）を使う。
指定されたloopのフレーム列と、それに含まれない活動中の差分を組み合わせて繰り返す。
これらはPORTALの表示間隔であり、WORLDの活動期間を変更しない。
KuroはWORLDが指定したポーズに一致する差分だけを使い、別のポーズへ勝手に循環させない。
腕組み・顔に手はそれぞれ`mirror-crossed-arms`・`mirror-hand-near-face`、
腰に手は既存の`mirror-hands-on-hips`に対応する。素材にない既存ポーズは通常画像へ戻す。

## 状態との対応

- WORLDの本人、活動種別、開始・終了予定時刻と現在の観測時刻を使う。
- 再読込みや次のsnapshotでも同じ活動の再生位置を保持する。
- 移動・就寝・活動の解除・別活動への切替時に趣味画像を残さない。
- WORLDが活動中の間は、終了予定時刻を過ぎてもPORTALで活動完了を確定しない。
- 読込み失敗や未対応の活動・ポーズを、実行できた活動として表示しない。
- 新しいPNGやJSONもアセット版の計算に含め、描画コードと素材のcache不一致を防ぐ。

## 追加と適用範囲

衣装・ポーズの定期生成は今回含まない。追加素材は本人、活動、phase、再生順、
基準位置の契約を維持してカタログへ追加する。
MioとMidoriには対応するWORLD実行機能と、本人専用の配置・所要時間設定が必要。
PORTALへ素材を入れただけでは日課の実行や本番配置を完了したことにならない。

## 受入確認

| 要求 | 消費経路 | 確認 |
|---|---|---|
| 22枚が配布成果物に含まれる | embed→静的HTTP→catalogのimage_path | Goの実HTTP handlerテストで各PNGの応答・寸法を確認 |
| WORLDの活動に対応する | snapshot→活動種別→描画フレーム | JSの活動別・時刻境界・無活動・切替テスト |
| 中断・再開で誤った動作を残さない | WORLD finish/stop→snapshot→通常描画 | WORLD/CORE lifecycle検査とJSの復帰テスト |
| 実際の室内で見える | 本番WORLD→PORTALの室内描画 | 実配置、家具の接地・遮蔽・縮尺は画面での受入が必要 |
